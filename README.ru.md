# Economy QA

**Локальная мастерская для проверки игровых экономик.** Импортируйте баланс, задавайте критерии, запускайте воспроизводимые сценарии и проверяйте, что именно изменилось.

[Открыть веб-интерфейс](https://hilsetapp.github.io/economy-qa/) · [CLI](#быстрый-старт) · [Схема модели](schemas/economy-v1.schema.json)

> Статус: ранний прототип / v0.1. Текущий прототип включает типизированную модель, импорт JSON/CSV, детерминированную симуляцию, статический поиск прибыльных циклов обмена, проверки баланса, CLI, веб-интерфейс и автономные HTML-отчёты. Адаптеры конкретных игровых форматов пока не реализованы.

## Почему такой подход

Универсальный визуальный симулятор пересекался бы с известными коммерческими продуктами и проектами с открытым кодом. Economy QA фокусируется уже: превратить существующие данные баланса в проверяемые правила, пригодные для локальной работы и CI. Мы не утверждаем, что такой подход уникален; гипотезу ещё предстоит проверить с владельцами серверов и инди-командами.

Одно ядро обслуживает две аудитории: RP-серверы и инди-игры. В репозитории есть примеры обеих экономик.

## Быстрый старт

Нужен Node.js 20 или новее.

```sh
npm install
npm run check
npm run build
node dist/cli.js validate examples/rp-server.json
node dist/cli.js simulate examples/indie-rpg.json --profile story-player --runs 1000 --seed 42
node dist/cli.js check examples/rp-server.json --runs 1000 --seed 42
node dist/cli.js report examples/indie-rpg.json --runs 1000 --seed 42 --out report.html
node dist/cli.js diff before.json after.json --profile story-player --runs 1000 --seed 42
npm run dev:web
```

CLI и веб-интерфейс обрабатывают входные данные локально и не загружают их. Веб-интерфейс выполняет до 20 000 прогонов для каждого профиля в текущей вкладке; кнопка **Export HTML report** сохраняет автономный отчёт. `check` возвращает код 1, если статический анализ находит ошибку или контракт не проходит; команду можно использовать в CI. `diff` использует одинаковые seed и число прогонов для обеих версий и показывает изменённые поля и значения до/после, игнорируя путь к файлу в provenance.

## Веб-интерфейс

Запустите `npm run dev:web` и откройте локальный адрес из вывода команды. Интерфейс позволяет выбрать один из примеров, загрузить `.json` или CSV описанного формата через файловый диалог или drag-and-drop, редактировать каноническую JSON-модель, запускать все именованные профили локально, проверять контракты и сохранять автономный HTML-отчёт. Чтобы интерфейс оставался отзывчивым, браузерный запуск ограничен 20 000 прогонов на профиль. Для работы не нужны аккаунт, сервер или отправка данных в сеть.

## Формат модели

JSON Schema: [`schemas/economy-v1.schema.json`](schemas/economy-v1.schema.json). Примеры: [`examples/rp-server.json`](examples/rp-server.json), [`examples/indie-rpg.json`](examples/indie-rpg.json). CSV-импорт поддерживает те же сущности в длинном формате: [`docs/csv-format.md`](docs/csv-format.md), [`examples/rp-server.csv`](examples/rp-server.csv).

Основные сущности:

- **Валюты** и начальные балансы.
- **Действия** с фиксированной длительностью, кулдауном, расходами, наградами и необязательной вероятностью успеха.
- **Обмены** с одной входной и одной выходной валютой. Они проверяются на повторяемые прибыльные циклы, но в симуляции пока не выполняются.
- **Профили** с длительностью сессии, числом сессий в день, горизонтом и явными весами выбора действий.
- **Контракты** для достижения этапа, доступности стока и диапазона баланса в последний день при заданной минимальной доле успешных прогонов.

Все входные значения — предположения дизайнера. Веса профиля — относительные веса выбора среди доступных действий, а не вероятности поведения реальных игроков. Текущая симуляция не моделирует лимиты инвентаря, открытие действий, рынки между игроками, налоги вне явно заданных действий, сезонность, адаптацию стратегии и офлайн-игру.

## Как интерпретировать результаты

Одинаковые данные модели, профиль, число прогонов, seed и версия ПО дают одинаковые результаты. Симулятор показывает p10/медиану/p90, среднее и диапазон конечных балансов, частоту действий и валовые суммы источников/стоков валют в модели.

Контракт проверяет предоставленную модель, а не задаёт универсальное определение баланса. Отчёт показывает предположения и предупреждения. Успешные проверки не доказывают сбалансированность экономики, отсутствие эксплойтов или репрезентативность для реальных игроков; отсутствие найденных проблем тоже не доказывает отсутствие эксплойтов.

Анализатор прибыльных циклов проверяет повторяемые обмены между валютами по отношению выхода к входу. Он не учитывает комиссии, ограничения объёма, случайность, требования разблокировки и доступность ресурсов сверх заданных ребер. Считайте результаты поводом для анализа, а не доказательством эксплойта в игре.

## Ограничения и дальнейшие шаги

1. Проверить процесс импорта и анализа на реальных конфигурациях RP-серверов и таблицах инди-игр.
2. Добавить адаптеры для форматов, выбранных пользователями, сохраняя ссылки на файл, строку и поле.
3. Расширять семантику симуляции только под подтверждённые сценарии и покрывать тестами каждое допущение.
4. Расширить сравнение версий и отчёты для CI, сохранив локальную обработку.

Не выдавайте синтетический профиль за прогноз поведения реальной когорты игроков. Отчёты и проверки в pull request должны быть воспроизводимыми и пригодными для ревью.
